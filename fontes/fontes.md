# 📚 Fontes selecionadas para o NotebookLM

Estas são as fontes abertas utilizadas na construção do Caderno Temático.

## 1. MDN — Overview of HTTP

**URL:** https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview

**O que estudar:**
- modelo cliente-servidor;
- requisições e respostas;
- componentes de mensagens HTTP;
- APIs baseadas em HTTP.

**Por que foi selecionada:** fornece uma visão técnica e consolidada do funcionamento do HTTP.

---

## 2. MDN — HTTP Request Methods

**URL:** https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Methods

**O que estudar:**
- GET;
- POST;
- PUT;
- PATCH;
- DELETE;
- métodos seguros e idempotência.

**Por que foi selecionada:** permite consultar a semântica dos métodos diretamente na documentação técnica.

---

## 3. Microsoft Learn — Azure REST API Reference

**URL:** https://learn.microsoft.com/en-us/rest/api/gettingstarted/

**O que estudar:**
- estrutura de requisições REST;
- URI;
- método HTTP;
- headers;
- body;
- status codes;
- JSON/XML;
- Authorization.

**Por que foi selecionada:** apresenta a comunicação com APIs REST de maneira aplicada.

---

## 4. OpenAPI Initiative — OpenAPI Specification

**URL:** https://spec.openapis.org/oas/

**O que estudar:**
- descrição de APIs HTTP;
- paths;
- operations;
- parameters;
- responses;
- schemas;
- documentação estruturada.

**Por que foi selecionada:** é a especificação oficial para descrição de APIs OpenAPI.

---

## 5. OWASP — API Security Top 10

**URL:** https://owasp.org/www-project-api-security/

**O que estudar:**
- riscos de segurança específicos de APIs;
- autorização;
- autenticação;
- consumo de APIs;
- configuração;
- inventário;
- SSRF;
- consumo de recursos.

**Por que foi selecionada:** acrescenta ao estudo uma perspectiva de segurança e DevSecOps.

---

## Observação sobre curadoria

As fontes foram escolhidas priorizando:

- acesso aberto;
- autoridade técnica;
- documentação primária;
- aplicabilidade prática;
- complementaridade entre fundamentos, documentação e segurança.

A seleção evita depender exclusivamente de blogs ou conteúdos secundários.
